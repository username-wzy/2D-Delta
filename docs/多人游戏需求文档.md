# Emoji Delta 多人联机 — 需求文档 v1.0

## 需求概述

将 Emoji Delta 从单机游戏升级为 **多人在线合作 PvE 游戏**。2-4 名玩家通过房间邀请进入同一张地图，共同搜索物资、对抗 Bot、各自撤离。第一阶段聚焦于「能一起玩」，PvP 玩家互打留到后续版本。

## 功能需求

### P0 — 第一阶段必须实现

- [ ] **P0-1 房间创建**：玩家在大厅可以创建一个房间，获得房间号（如 6 位字母数字）
- [ ] **P0-2 邀请加入**：其他玩家输入房间号加入同一房间，房主可以看到已加入的玩家列表
- [ ] **P0-3 房主控制**：房主点击「开始游戏」，所有人同时进入同一张地图
- [ ] **P0-4 多玩家同步**：所有玩家在同一地图中可以看到彼此的位置、移动、射击
- [ ] **P0-5 合作 PvE**：所有玩家可以共同对抗 Bot，Bot 对每个玩家独立做出反应
- [ ] **P0-6 共享世界**：战利品对所有玩家可见（先到先得），Bot 死亡掉落所有人都能拾取
- [ ] **P0-7 各自撤离**：每个玩家独立完成撤离（走到撤离点 → 10s 倒计时 → 撤离成功），先撤离的人离开游戏，其他人继续
- [ ] **P0-8 死亡处理**：玩家死亡后装备遗失，进入观察状态（可以看到其他玩家），其他玩家可以拾取死亡玩家的掉落背包

### P1 — 后续版本

- [ ] **P1-1 PvP 战斗**：玩家之间可以互相攻击，命中判定与护甲穿透同 PvE 公式
- [ ] **P1-2 击杀奖励**：击杀其他玩家可以获得对方背包中的战利品
- [ ] **P1-3 语音/快捷消息**：游戏内简单通信（"发现敌人""需要帮助""撤离"等快捷消息）

### P2 — 可选功能

- [ ] **P2-1 观战切换**：死亡后可以在其他玩家视角之间切换
- [ ] **P2-2 队伍语音**：WebRTC 语音通话
- [ ] **P2-3 排位系统**：基于撤离成功率的排位分

## 非功能需求

- **网络性能**：服务器 60Hz Tick，客户端 20Hz 快照广播，延迟 < 100ms 可接受
- **安全性**：服务器权威判定所有伤害和移动，客户端只发送输入
- **可靠性**：玩家断线 30s 内可重连恢复，超时判定死亡
- **并发**：支持多个房间同时进行（每个房间独立 Match 实例）

## 边界与约束

- **不包含**：第一阶段不做 PvP 伤害、不做自动匹配、不做排位
- **技术限制**：C# .NET 8 服务器 + HTML5 Canvas 客户端，WebSocket 通信
- **外部依赖**：无需外部服务，玩家通过 IP/端口直连服务器
- **房间生命周期**：房间在所有玩家撤离/死亡后自动销毁

## 验收标准

### P0-1 房间创建
- Given 玩家已登录大厅，When 点击「创建房间」，Then 显示 6 位房间号，可以复制分享

### P0-2 邀请加入
- Given 玩家已登录大厅，When 输入有效的房间号并点击「加入」，Then 进入房间等待界面，看到已加入的玩家列表

### P0-3 房主控制
- Given 房间内有 2-4 名玩家，When 房主点击「开始游戏」，Then 所有玩家同时加载同一张地图，出生在不同位置

### P0-4 多玩家同步
- Given 两名玩家在同一地图中，When 玩家A移动或射击，Then 玩家B的屏幕上能实时看到玩家A的位置变化和射击动作

### P0-5 合作 PvE
- Given 两名玩家在同一地图中，When 玩家A开枪引来 Bot，Then Bot 会攻击最近的或开枪的玩家，不会只追一个人

### P0-6 共享世界
- Given 地图上有战利品 💎，When 玩家A拾取了该战利品，Then 玩家B看到该战利品消失

### P0-7 各自撤离
- Given 玩家A在撤离点完成 10s 倒计时，When 撤离成功，Then 玩家A退出游戏进入结算画面，玩家B继续游戏不受影响

### P0-8 死亡处理
- Given 玩家A被 Bot 击杀，When 死亡后，Then 玩家A看到观察画面（队友视角），其背包以 🎒 形式掉落在地图上，其他玩家可以拾取
